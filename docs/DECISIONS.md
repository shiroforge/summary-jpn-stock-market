## D-03 TOPIX の値は Yahoo!ファイナンス（日本版）のページから1日1回取得する
- **検証結果（2026-09-26）**: yfinance では `^TOPX` / `998405.T` が 404。stooq は JS チャレンジで取得不可。
- Yahoo!ファイナンス（日本版）の `998405.T` ページには終値・前日比・騰落率が埋め込まれており、取得できる。
- ただし同サイトの利用規約はスクレイピングを想定していない。1日1リクエストに抑え、失敗したら後述の推計値で代用する。J-Quants に移行したら公式値に切り替える。
- **代替案（フォールバック）**: TOPIX 構成銘柄の騰落率をTOPIXウエイトで加重した推計値。9/25 は推計 +1.34% に対し実際は +1.31% だった。

## D-04 33業種は「TOPIXウエイト加重の推計値」
- JPX が無料で公開している `topixweight_j.csv`（全構成銘柄のコード・業種・TOPIXウエイト、月次更新）を銘柄マスタとして使う。
- 業種騰落率 = Σ(銘柄騰落率 × TOPIXウエイト) / Σ(TOPIXウエイト)。公式の業種別指数と同じ考え方（浮動株時価総額加重）で、誤差は小さい。
- 画面には「推計値」バッジを出す。J-Quants Standard に移行したら公式指数に切り替え、`sectors_official=True` にする。
- 対象はTOPIX構成銘柄（約1,640銘柄）。グロース市場の銘柄は33業種集計に含めないが、テーマでは個別に指定できる。

## D-05 yfinance はアクセス制限（429）を前提に設計する
- **検証結果**: 約1,640銘柄×3か月を一括取得すると約40秒。初回で約390銘柄が欠け、再取得でほぼ埋まった。ただし短時間に繰り返すと `YFRateLimitError`（HTTP 429）で全件失敗した。
- 対策:
  1. 日次の取得は **1回のバッチ（直近数営業日分のみ）** に限る。長い履歴は `data/prices/` にキャッシュして追記していく。
  2. 100銘柄ずつに分け、間に待ち時間を入れ、欠けた銘柄だけを指数バックオフで再取得する。
  3. 取得できた銘柄のTOPIXウエイト合計（カバー率）を出し、95%未満なら警告を出す。
  4. GitHub Actions の IP でも制限されやすいかは Phase 2 で確認する。だめなら取得だけをローカルか別の実行環境に移すか、J-Quants への移行を前倒しする（費用が発生するので承認が必要）。

## D-19 毎日の自動実行（GitHub Actions）と Discord 通知（2026-09-27）

## D-21 トレンドページ（P3-1、2026-09-27）
- 場所は `/trends/`。上部のナビから開ける。「33業種」と「テーマ」をタブで切り替える。

## D-22 配信を16:00前後に早める（ユーザーの要望、2026-09-27）
- 実行は 15:50（1回目）→ 16:30 → 17:30 JST（最終回）の3回。どれかの回で生成できれば、残りの回は「生成済み」として何もしない。
- 15:50 にした理由: 大引けは 15:30 で、yfinance の個別株データは約20分遅れる。Actions は予定時刻より数分〜十数分遅れて始まり、処理に1〜2分かかるため、16:00 前後に届く見込み。
- 早く実行するほど「データがそろう前に作ってしまう」危険が増すため、最終回以外（`--early`）では次の場合に終了コード75で見送り、次の回に任せる:
  1. 当日の終値を取得できた銘柄が、TOPIX ウエイトの95%未満
  2. TOPIX の公式終値（Yahoo!ファイナンス）がまだ当日分になっていない
  - いずれも日経平均の鮮度チェックに加えて行う。最終回と手動実行では、欠けがあっても警告付きで生成する。
- 16:00 ちょうどの配信を保証したい場合は、外部の cron（例: cron-job.org）から workflow_dispatch を呼ぶ方法がある。今は不要と判断した。
- 実際に何時に届いたかは、最初の数営業日の実行時刻を見て確認し、必要なら15:50を前後させる。

## D-23 適時開示（TDnet）の取り込み（P3-3、2026-09-27）
- 取得元: TDnet の公開一覧ページ `release.tdnet.info/inbs/I_list_NNN_YYYYMMDD.html`（1ページ100件）。公式 API はないため、一覧ページを1ページずつ0.5秒あけて読む。保存するのは時刻・コード・社名・見出し・PDF の URL だけで、PDF 本体は取得しない。利用規約上は Yahoo!ファイナンスの TOPIX と同じくグレーなので、1日1回（最大でも数十ページ）に抑える。
- 時間の区切り:
  - 前営業日 15:30 〜 当日 15:30 未満 → 「当日の値動きの材料」。ランキング、テーマの構成銘柄、業種の牽引銘柄に、分類のついた開示を1銘柄あたり2件まで付ける（注目の分類を優先し、その中では新しい順）。
  - 当日 15:30 以降 〜 生成時刻 → 「引け後」（翌日の材料）。15:30 ちょうどの開示は引け後に数える。
  - 16:00 の配信では、夕方以降の開示は含まれない（ページにも明記）。
- 分類: 見出しのキーワードで分ける。分類は TOB・MBO、上方修正、下方修正、増配、減配、自社株買い、株式分割、業績修正、決算、提携・買収、増資・希薄化、特別損失、株主優待、報道への回答。
  - 除外語で「取得状況」「公開買付けの結果」「訂正」などを外す。
  - トーン（pos/neg）は機械的な目安で、プラスとマイナスの両方に当たる見出しは neutral にする（例: CB 発行と同時の自社株買い）。
- 一覧は「注目の分類」だけを TOPIX ウエイトの大きい順に最大40件表示する。Discord には上位3件を載せる（引け後の開示があれば引け後を優先）。
- 実データ（9/25）での確認: 小林製薬 +17%（報道への回答）、三十三FG +8.8%（増配・業績修正）、生化学工業 −8.9%（業績修正）、清水建設 −6.0%（CB 発行）など、大きく動いた銘柄の多くで理由が見えるようになった。
- 今後の改善候補: 業績修正の方向（上方か下方か）は見出しからは判別できないことが多い。LLM の段階で PDF を要約すれば判別できる。

- **大引けまでの開示**（前営業日 15:30 〜 当日 15:30）: 当日の終値ベースの騰落率を表示する。株価データを持っていない銘柄は、yfinance から直近2週間分をその場で取得する。場中の開示では、開示前の値動きも含む（ページに明記）。

## D-26 TOPIX のローソク足と米国債のローソク足（ユーザーの指摘、2026-09-27）
- 指摘: TOPIX のチャートがローソク足になっていない。これまでは実際の四本値がなく、構成銘柄からの推計を折れ線で描いていた。
- 対応:
  - Yahoo!ファイナンスの時系列ページ（`/quote/998405.T/history?page=N`、1ページ20営業日）から TOPIX の日足の四本値を取得し、株価データの保存先に `998405.T` として保存する。初回は年初分まで（約10ページ）さかのぼり、2回目以降は1ページ目だけ読む。
  - 当日の四本値は、指数ページの `mainDomesticIndexDetail`（始値・高値・安値）と公式終値から作る。
  - TOPIX の 5日・20日騰落率とミニチャートも、実際の終値から計算するようにした（9/25: 推計 5日+2.40%・20日+1.12% → 実際 +2.26%・+0.85%）。

## D-27 定時実行の時刻を毎時0分・30分からずらす（ユーザーの要望、2026-09-29）
- 事象: 9/28・9/29 の 15:50・16:30・17:30 の定時実行が起動しなかった（9/28 は手動実行で配信）。22:00 の回（`0 13`）は約7時間遅れて翌 4:57 JST に起動した。
- 原因: 設定の誤りや UTC/JST の取り違えではない（取り違えならずれは9時間ちょうど）。GitHub Actions の定時実行は保証がなく、混雑時は遅延・取りこぼしが起こる。毎時0分・30分は特に混む。
- 対応: cron を 15:47 / 16:33 / 17:33 / 22:07 JST（`47 6` / `33 7` / `33 8` / `7 13`）に変えた。最終回・夜間の判定に使う cron 文字列も合わせて変えた。
- これで改善しない場合は、外部の cron サービスから `workflow_dispatch` を起動する方式を検討する（トークンを外部に預けるため、ユーザーの判断が必要）。
