## D-01 言語・ツール: Python 3.13 + uv
- 3.14 もローカルにあるが、pandas / yfinance などのホイールが確実に揃っている 3.13 に固定する。
- 品質ゲートは ruff（lint・format）、mypy --strict、pytest。

## D-02 DailySummary を唯一の契約にする
- 生成側（collect / analyze）と消費側（render / notify）は `src/jpmarket/models.py` の `DailySummary` だけでつながる。
- スキーマを変えたら `SCHEMA_VERSION` を上げ、ここに記録する。過去の `data/daily/*.json` は古いスキーマのまま読めるよう、フィールドは追加のみ・既定値ありを原則にする。

## D-03 TOPIX の値は Yahoo!ファイナンス（日本版）のページから1日1回取得する
- **検証結果（2026-09-26）**: yfinance では `^TOPX` / `998405.T` が 404。stooq は JS チャレンジで取得不可。
- Yahoo!ファイナンス（日本版）の `998405.T` ページには終値・前日比・騰落率が埋め込まれており、取得できる。
- ただし同サイトの利用規約はスクレイピングを想定していない。1日1リクエストに抑え、失敗したら後述の推計値で代用する。J-Quants に移行したら公式値に切り替える。
- **代替案（フォールバック）**: TOPIX 構成銘柄の騰落率をTOPIXウエイトで加重した推計値。9/25 は推計 +1.34% に対し実際は +1.31% だった。

## D-04 33業種は「TOPIXウエイト加重の推計値」
- JPX が無料で公開している `topixweight_j.csv`（全構成銘柄のコード・業種・TOPIXウエイト、月次更新）を銘柄マスタとして使う。
- 業種騰落率 = Σ(銘柄騰落率 × TOPIXウエイト) / Σ(TOPIXウエイト)。公式の業種別指数と同じ考え方（浮動株時価総額加重）で、誤差は小さい。
- 画面には「推計値」バッジを出す。J-Quants Standard に移行したら公式指数に切り替え、`sectors_official=True` にする。
- 対象はTOPIX構成銘柄（約1,640銘柄）。グロース市場の銘柄は33業種集計に含めないが、テーマでは個別に指定できる。

## D-05 yfinance はアクセス制限（429）を前提に設計する
- **検証結果**: 約1,640銘柄×3か月を一括取得すると約40秒。初回で約390銘柄が欠け、再取得でほぼ埋まった。ただし短時間に繰り返すと `YFRateLimitError`（HTTP 429）で全件失敗した。
- 対策:
  1. 日次の取得は **1回のバッチ（直近数営業日分のみ）** に限る。長い履歴は `data/prices/` にキャッシュして追記していく。
  2. 100銘柄ずつに分け、間に待ち時間を入れ、欠けた銘柄だけを指数バックオフで再取得する。
  3. 取得できた銘柄のTOPIXウエイト合計（カバー率）を出し、95%未満なら警告を出す。
  4. GitHub Actions の IP でも制限されやすいかは Phase 2 で確認する。だめなら取得だけをローカルか別の実行環境に移すか、J-Quants への移行を前倒しする（費用が発生するので承認が必要）。

## D-06 グロース250・JPX日経400は連動ETFで代用する
- `2516.T`（東証グロース250 ETF）と `1591.T`（NEXT FUNDS JPX日経400）の値を表示し、「ETF代用」バッジを付ける。騰落率はほぼ一致するが、水準は指数と異なる。

## D-07 ニュースは RSS の見出しとリンクだけを使う
- 使えることを確認したもの: NHK経済、Yahoo!ニュース（経済・国際）、Google News（検索・ビジネス）、東洋経済、日経速報（wor.jp 経由）
- 取得できなかったもの: ロイター、Bloomberg（wor.jp 経由で 403）、株探（404）、みんかぶ（403）
- 本文は保存・転載しない。テーマやセクターへのタグ付けは `config/themes.yaml` のキーワードで行う。

## D-08 描画はサーバー側で SVG/HTML を生成し、チャートライブラリは使わない
- 計画では ECharts を想定していたが、描画するのは横棒・ヒートマップ・スパークラインだけなので、Jinja2 と CSS で十分と判断した。
- 利点: JS なしでも読める、ページが軽い、Discord のプレビューやサムネイルにも中身が出る、Artifact の CSP の制約を受けない。
- JS は、ツールチップ、タブ、上昇色の切り替え（localStorage に保存）だけに使う。
- 複雑なインタラクティブ表示が必要になったら、その時点で ECharts を再検討する。

## D-09 上昇色は既定を「赤」（日本式）にし、閲覧者が切り替えられるようにする
- G1 でユーザーに確認する。どちらに決まっても、切り替えボタンは残す。
